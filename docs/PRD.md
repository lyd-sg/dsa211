### 1. Purpose and intended deliverable

**Problem.** Evaluate whether historical browsing-session variables predict a session-level purchase (`Revenue=1`) sufficiently well to justify a defensible classifier and any stated operational interpretation.

**Audience.** DSA211 instructor/markers and a statistically literate reader. **Artifact.** A concise, fully executable Python notebook presenting an academic predictive classification analysis, not a deployed e-commerce product.

**Main outcome [Confirmed during grilling, Q1].** A **prediction-focused** project: compare eligible models on defensible validation, explain what the data support, select a model reproducibly, and communicate limitations. The project is not a coefficient-inference or causal voucher-effect study.

**Secondary application [Confirmed Q2–Q5, Q17, Q24].** Select the classifier using predictive performance, then use the **primary cost-based threshold 2/3 (≈0.667)** derived from Lecture 5 under a hypothetical 20% voucher discount and 50% reference incremental conversion. Predicted buyers receive no voucher; predicted non-buyers receive a hypothetical voucher. **On training out-of-fold predictions**, conduct a separate, non-optimising threshold sensitivity analysis at the training purchase base rate (approximately 0.155), 0.500, 0.667, and the training-derived sensitivity–specificity crossover, holding discount and reference conversion fixed. For the **primary threshold**, hold classifier and recipient assignments fixed while comparing simulated revenue at **10%, 25%, 50%, and 100%** assumed incremental conversion. Evaluate the selected model once on the final 20% test with primary threshold 0.667 only. Report unfavourable outcomes, too; **do not choose classifier or threshold by maximum simulated revenue**. The application is illustrative, not a deployable live voucher system or causal estimate.

**Original working proposal [Resolved Q16].** The previous two-page working proposal described live sales support for likely buyers and a hypothetical 5:1 error-cost ratio. The user confirmed it is **revisable**, so the current three-classifier, prediction-focused study with illustrative voucher application supersedes that proposal. ### 7A. Agreed threshold mathematics — for implementation and verification

Let `A` be the common no-discount order value; `d=0.20` the voucher discount; `q=0.50` the **reference incremental conversion probability among otherwise non-buyers**; and `p` the model-predicted probability of buying **without** a voucher. Assume existing buyers still buy if offered a voucher; all voucher buyers pay `0.80A`; observed `Revenue` records no-voucher outcomes.

- Giving a voucher to an actual existing buyer (predicted non-buyer: FN) forgoes `C_FN = dA = 0.20A`.
- Not giving a voucher to an actual non-buyer (predicted buyer: FP) forgoes *expected* incremental revenue `C_FP = (1-d)qA = 0.80 × 0.50 A = 0.40A`.
- **Primary theoretical threshold** (Lecture 5): `t* = C_FP / (C_FP + C_FN) = 0.40/(0.40+0.20) = 2/3 ≈ 0.667`. Keep this threshold **fixed across conversion-rate scenarios and for the final held-out audit**. The distinct training-only threshold-sensitivity analysis below compares other defensible cutoffs without changing the primary policy.
- For any scenario `q_s ∈ {0.10, 0.25, 0.50, 1.00}`, let `TP, FP, FN, TN` use observed `Revenue=1` as the positive class **at the fixed classification rule**. No-voucher revenue: `R0/A = TP + FN`. Expected model-voucher revenue: `Rq/A = TP + 0.80 FN + 0.80 q_s TN`. Simulated difference: `ΔRq/A = 0.80 q_s TN − 0.20 FN`. Thus only the assumed incremental conversion rate changes across scenarios, not predicted probabilities or assignments.
- Cost-based `t*` is theory-based **under assumptions**, not a guarantee of empirical optimality, calibrated probabilities or actual causal uplift. The real `q` is unknown and there are no voucher intervention labels.

### 7B. Agreed threshold sensitivity — **exact four coursework-supported references** [Confirmed Q24]

Threshold choice is **application-driven** (Lecture 5 §§7.2–7.3 and classification labs). These **four** pre-specified comparison policies must be recorded and compared **only on the winning classifier's training out-of-fold predictions**:

| Threshold / reference | Exact definition and rationale |
|---|---|
| **Training purchase base rate** (about **0.155**) | `t_base = mean(y_train)`, computed after the stratified 80/20 split; Lecture 5's class-prevalence reference, **not** a universally optimal operating point. |
| **0.500** | Conventional equal-probability/default binary classification cutoff, included as a benchmark. |
| **0.667** (exactly **2/3**) | **Primary policy** from the Lecture 5 relative opportunity-cost formula under `d=0.20, q_ref=0.50`. This is the **only threshold used in the final test audit**. |
| **Sensitivity–specificity crossover** | A training-derived cutoff at which sensitivity and specificity are as close as achievable, computed from the selected model's **out-of-fold training predicted probabilities**; report the actual resulting threshold and the two rates. It is a balanced-classification reference, **not** intrinsically cost-optimal. |

**Two distinct sensitivity dimensions — do not conflate them:**
1. **Threshold sensitivity (training OOF only):** with discount **20%** and assumed incremental conversion **50% held fixed**, compare the four cutoffs above on **sensitivity, specificity, precision, percentage receiving vouchers, and hypothetical revenue**. These comparisons are descriptive robustness checks, **not threshold optimisation or additional model selection**. Keep the actual primary threshold at **0.667**, regardless of which alternative shows highest simulated revenue.
2. **Conversion sensitivity (primary 0.667 fixed):** vary assumed incremental conversion among otherwise nonbuyers over **10%, 25%, 50%, 100%**, keeping model, threshold and voucher recipients unchanged. The **final held-out 20%** is evaluated **once for the single CV-selected model at 0.667**. Illustrative voucher outcomes use that already-frozen held-out classification, not threshold search.

**Limitations:** threshold results depend on the distribution and calibration of predicted probabilities. AUC ranks predictions and does **not** guarantee calibration, especially for Naive Bayes. Neither the crossover nor simulated revenue establishes a uniquely correct threshold or actual voucher uplift.
